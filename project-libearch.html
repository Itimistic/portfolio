Overview

Know what you're borrowing before you borrow it

Libearch is a library management system built in Java. It goes beyond cataloguing — users can search for books, read a summary before deciding to borrow, and manage their checkout all in one place. The goal was to make the library feel less like a filing system and more like a bookstore you can browse.

Research

Why borrowing feels like guesswork

Traditional library systems show you a title, author, and shelf number — then you walk to the shelf and hope the book is what you needed. Libearch addresses the gap between searching and committing to a borrow.

Target Users
Students and library visitors who want to find and evaluate books efficiently before committing to borrowing.
Core Problem
Library catalogues tell you a book exists but not whether it's relevant to you — leading to wasted trips and poor borrowing decisions.
Design Goal
A search-first system with readable summaries, so users can make informed borrowing decisions before leaving their seat.

Designing the system

Key Design Decision

Summary before borrow

Adding a readable book summary to each listing meant users could make a confident decision before checking out — reducing abandoned borrows and making the system feel more like a discovery tool than a catalogue.

Small additions to information architecture change how people feel about a system.

Reflection

What I learned

Libearch pushed me into backend thinking for the first time. Designing the UX was one challenge — building the data model and borrowing logic in Java was another. Understanding how data flows through a system made me a better designer, because I started to see constraints before they became problems. It's a skill I still use when designing anything data-driven.
